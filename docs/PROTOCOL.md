# UT70 侧面 HID 协议

本页记录解析规则和已确认的限制；可直接查找发送帧与接收示例的表格见 [UT70 指令速查表](UT70%20指令速查表.md)。协议来自 VID `19F5`、PID `6666`、硬件 2.7、应用 V3.5 的仪表，其他版本可能不同。

## 报告格式

HID 数据区为 64 字节。hidapi 写入时在前面加 `00` Report ID，共 65 字节；WebHID 单独指定 Report ID `0`。读取的 64 字节不含 Report ID。短帧在末尾补 `00`。

应用帧为 `EE 命令 长度 载荷 累加和 [FF]`：长度是载荷字节数，校验是从 `EE` 到载荷末尾的低 8 位累加和。60 字节载荷的 `0x08` 测量帧恰好占满 64 字节，没有 `FF`。应用与升级模式共用 VID/PID，应通过版本回复的模式字段区分。

## 主要上报字段

### 版本 `0x02`

13 字节载荷：偏移 `0..3` 依次为 Boot/IAP、应用、硬件、UI 版本字段；`4..11` 为 8 字节 ASCII 序列号；`12` 为模式（`00` 应用、`01` 升级）。UI 版本字段不是当前界面编号，升级模式中的应用字段也不能用作已安装应用版本。波形显示页可能不回复版本查询，但测量仍会继续。

### 测量 `0x08`

60 字节载荷均为小端：

| 载荷偏移 | 内容 |
| ---: | --- |
| 0–19 | `float32[5]` 电压 V |
| 20–39 | `float32[5]` 电流 A |
| 40–49 | `uint16[5]` D+ 原始值，除以 `10000` 得 V |
| 50–59 | `uint16[5]` D− 原始值，除以 `10000` 得 V |

相同索引组成一个采样点。4、10、50、200 SPS 每帧使用第 0 组，500、1000 SPS 使用 5 组。帧内没有设备时间戳、当前快充协议、功率、负载电阻或累计电量/能量；功率为 `V×I`，负载电阻为 `V/I`。软件按每点 `I/(3600×SPS)` Ah、`V×I/(3600×SPS)` Wh 累加，界面显示 mAh/Wh；DLL 的采样间隔表与 `1000/SPS` 一致。

### 采样率 `0x70` 与界面 `0x03`

采样率索引 `0..5` 对应 `4, 10, 50, 200, 500, 1000` SPS；上报载荷第 2 字节为索引，第 3–4 字节为小端 SPS。仪表按键改动采样率或界面时也会主动上报，客户端据此同步下拉框。界面编号及行为见 [UI 文档](UI.md)。

`0x70` 查询回复曾回显请求的校验字节，即使载荷已变化。客户端只在等待对应查询时接受这一特例，其他帧仍须通过正常校验。

### 快充检测 `0x20`、`0x21`

`0x20` 自动检测会与供电端握手、可能改变输出电压，应先移除负载。`0x20` 结果载荷：偏移 0 为状态，偏移 1 为协议编号，偏移 2–5 为小端 `uint32` 能力掩码；实测还有偏移 6，含义未定。`0x21` 文字结果载荷：偏移 0 为协议编号，偏移 1 为是否支持（`01` 支持），偏移 2 起为说明文字，客户端按 GBK 解码。实测 `0x21` 长度字段比实际载荷少 1 字节；仅在后一字节的累加和正确时兼容。

优先展示 `0x21` 原文，不把 `0x20` 的所有掩码位直接解释为电压档位。扫描结果表示供电端支持什么，**不代表当前正在协商的协议**；普通测量帧也不含这个状态，因此主界面默认显示“未识别”。客户端在最后一条结果后静默 18 秒或总计 120 秒时结束扫描等待；没有观察到明确的完成帧。DLL 还提供手动设置协议档位的 `0x20` 请求格式，见速查表；这些请求尚未实机验证。

## 验证边界

Windows 已验证应用帧、采集、采样率、自动检测与界面操作；macOS 已验证采集、曲线和界面回读；Linux 已验证采集、曲线及界面查询。自动检测尚未在 macOS/Linux 实机验证。升级模式另见 [固件文档](FIRMWARE.md)。本页是逆向记录，并非厂商规范。
