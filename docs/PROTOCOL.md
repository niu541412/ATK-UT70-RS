# UT70 侧面 HID 接口

本文是逆向记录，并非厂商规范。已验证样本：VID `0x19F5`、PID `0x6666`，硬件版本 `27`（2.7）、应用版本 `35`（V3.5）、Boot/IAP 字段 `10`。应用模式和升级模式共用 VID/PID，必须读取版本回复的模式字段区分。原始抓包未纳入仓库。

## HID 报告

输入和输出报告各为 64 字节。hidapi 写入参数为 **65 字节**：第一个字节是零 Report ID，后面才是 64 字节报告；读取返回 64 字节，不包含 Report ID。短帧以零填充。Windows 抓包中的应用模式中断端点为 OUT `0x01`、IN `0x82`；使用 HID API 时不需硬编码端点。

## 应用帧

去掉 Report ID 后：`EE 命令 长度 载荷 累加和 [FF] 零填充`。累加和覆盖 `EE` 到载荷最后一个字节，取低 8 位。载荷最大 59 字节。60 字节载荷的测量帧占满 64 字节，校验字节在最后一位，因此没有空间放 `FF`；接收端不能强制要求它有帧尾。

版本查询 `0x02` 示例：写入前 8 字节 `00 EE 02 02 00 00 F2 FF`，随后补零至 65 字节。

| 命令 | 请求载荷 | 已知回复或行为 | 证据边界 |
| --- | --- | --- | --- |
| `0x00` 探测 | `00 00` | 升级模式回复载荷 `71 01` | 官方抓包 |
| `0x02` 版本/模式 | `00 00` | 13 字节载荷，见下节 | 官方抓包、实机 |
| `0x03` 仪表界面 | 查询 `00 00 00 00`；切换 `编号 01 01 01` | 回复首载荷字节是即时编号 | macOS 实机、Windows 官方客户端观察 |
| `0x08` 测量 | 无需请求 | 持续上报 60 字节载荷 | 三平台实机 |
| `0x70` 采样率 | 查询 `00 00 00 00`；设置 `01 索引 SPS低字节 SPS高字节` | 回复载荷第 1 字节为索引 | 官方抓包、实机 |
| `0x20` 快充检测/控制 | 自动检测 `00 00 00 00`；单协议控制格式尚待验证 | 自动检测切换仪表至界面 `5`，随后异步返回 `0x20`、`0x21` | Windows DLL 实机及 USB 抓包 |
| `0x21` 快充文字结果 | 无需单独请求 | 异步返回协议名、是否支持及档位文字 | Windows DLL 实机及 USB 抓包 |
| `0x40`、`0x42`、`0x50` | 离线记录、记录组信息、EEPROM | 布局或回复未完整还原 | DLL 静态线索 |
| `0x60` 进入升级模式 | `01 00` | 未实机发送；目前通过按键进入 | DLL 静态线索 |

### 版本回复 `0x02`

应用模式样本的载荷前四字节为 `0A 23 1B 00`，随后是 8 字节 ASCII 序列号及模式字节 `00`。完整样本中的设备序列号不在公开文档中列出。

| 载荷偏移 | 内容 |
| ---: | --- |
| 0 | Boot/IAP 版本字段，样本 `10` |
| 1 | 应用版本，样本 `35` |
| 2 | 硬件版本，样本 `27` |
| 3 | UI 版本字段；不是当前界面编号 |
| 4–11 | ASCII 序列号字段 |
| 12 | `00` 应用模式，`01` 升级模式 |

升级模式中载荷偏移 1 曾为 `12`，不能解释成已安装应用版本。Windows 与 Linux 都观察到：停留在“波形显示”时，`0x02` 偶发无回复，而 `0x08` 测量仍继续；回到“基本测量”后查询恢复。因此不能因版本查询超时就判定 HID 已断开。

### 测量 `0x08`

60 字节载荷均为小端：0–19 为 `float32[5]` 电压 V，20–39 为 `float32[5]` 电流 A，40–49 为 `uint16[5]` D+ 原始值，50–59 为 `uint16[5]` D− 原始值。D+/D− 除以 `10000` 得 V。相同索引组成一个测量点；4、10、50、200 SPS 每帧取第 0 组，500、1000 SPS 每帧取 5 组。功率由主机计算 `P=V×I`；客户端可另算负载电阻 `R=V/I`，仅在电流大于 1 mA 时绘制。它不等同于“线阻模式”测得的线阻。帧内没有设备时间戳，客户端按接收时刻和采样率估计每点时间。此帧不含快充协议或档位信息。

### 采样率 `0x70`

索引 `0..5` 对应 `4, 10, 50, 200, 500, 1000` SPS。查询帧 `EE 70 04 00 00 00 00 62 FF`；设置 500 SPS 为 `EE 70 04 01 04 F4 01 5C FF`。

**校验特例：**查询回复曾为 `EE 70 04 01 04 00 00 62 FF`。载荷已更新为索引 `04`，但校验字节仍是请求的 `62`。只在等待对应 `0x70` 请求时接受这个回显校验，不能全局忽略错误校验。

### 界面 `0x03`

查询 `EE 03 04 00 00 00 00 F5 FF`；切换到波形显示 `EE 03 04 01 01 01 01 F9 FF`。已知编号：`0` 基本测量、`1` 波形显示、`2` 数据记录、`3` 功能应用、`4` 手动触发、`5` 自动检测、`11` 监控模式、`18` 线阻模式、`19` DASH 检测、`20` E-Marker 检测、`29` 设置、`255` 其他。详细行为见[界面说明](UI.md)。

### 自动检测快充协议 `0x20`、`0x21`

官方 DLL 的 `AutoDetectionProtocol()` 在应用模式下发送 `EE 20 04 00 00 00 00 12 FF`。实机抓包证实此请求先触发 `0x03` 上报界面 `5`（自动检测），随后设备逐项上报结果。扫描会对被测供电端执行握手并可能改变输出电压；需在供电端没有负载时主动启动，且不要把每次检测的结果当成仪表固定能力。

`0x21` 文本结果的载荷：偏移 0 为协议编号，偏移 1 为结果标志（`01` 支持，`00` 未检测到），偏移 2 起至校验字节前为文字（官方 Windows DLL 用系统默认代码页解码；本客户端按 GBK 解码）。**实机帧的长度字段比实际载荷少 1 字节**，接收时仅在后一字节的累加和正确时兼容。例如 `EE 21 0E 09 00 50 44 20 6E 6F 74 20 65 78 69 74 0D 0A 1C FF` 表示编号 `9` 的 PD 未检测到，文字为 `PD not exit`（设备原文如此）。

`0x20` 位掩码结果的载荷至少 6 字节：偏移 0 为状态字，偏移 1 为协议编号，偏移 2–5 为小端 `uint32` 掩码。实机是 7 字节载荷，偏移 6 尚未确定。例：`EE 20 07 00 03 84 48 00 00 01 E5 FF` 表示 FCP（编号 `3`），掩码 `0x00004884`。官方 DLL 将偏移 1 作为协议枚举、偏移 2 起四字节作为掩码；其回调没有解析第 0、6 字节。

已见编号：`0` BC1.2、`1` QC2、`2` QC3、`3` FCP、`4` SCP、`5` AFC、`6` PE1、`7` PE2、`8` VOOC、`9` PD、`12` Apple 2.4A、`13` VFCP、`20` UFCS。`0x21` 的文字直接给出电压/电流档位，优先展示原文。DLL 中掩码位 `0x80/0x800/0x4000` 分别对应 5/9/12 V，但还含状态标志和其他协议专用位，不应把全部掩码简单转换为档位列表。

右侧供电协议检测面板只展示供电端协议。DASH 检测和 E-Marker 检测是仪表功能界面，不在此处显示方块。DASH 可从“仪表界面”下拉框切换；E-Marker 远程切换会令仪表白屏，客户端只在下拉框中显示其名称，需用仪表按键进入。

本次无负载供电端的结果包括：PD、UFCS、PE1/2、VOOC、VFCP 未检测到；Apple 2.4A、BC1.2 DCP 5V 1.5A、FCP 5/9/12V、AFC 5/9/12V、SCP 5.5–10V 2A 20W、QC2 5/9/12V、QC3 3.6–12V 检测到。第二次 Rust HID 实机扫描持续观察 75 秒，最后一条在第 45.4 秒出现，之后无新结果；未观察到明确的完成帧。客户端据此在最后一条结果后静默 18 秒时结束等待，另设 120 秒上限。波形 `0x08` 仍持续上报。

**当前协商协议的限制：**普通 `0x08` 测量帧不包含协议编号；基线抓包也没有独立的被动协议状态帧。官方客户端基本测量页的“协议日志”在这次无负载连接时为空。实际负载测试中，仪表屏幕显示 QC 2.0、约 9 V，官方 DLL 被动监听 35 秒未收到协议事件；直接读取 HID 25 秒及重新插入负载期间的 60 秒，分别只收到 2501 和 6001 个 `0x08` 测量帧，没有其他命令帧。此时 D+≈3.28 V、D−≈0.64 V，但仅凭 D+/D− 和输出电压无法可靠识别所有当前协议。`0x20`/`0x21` 扫描结果是供电端支持列表，不能据此判断当前正在使用哪一种协议。客户端主界面因此显示“未识别”，不会在启动时自动执行可能改变供电电压的协议扫描。若后续发现可靠的被动状态字段，再补充当前协议解析。

## 验证边界

Windows：应用帧、采集、采样率、快充自动检测（官方 DLL、原始 USB 抓包、Rust HID 及桌面界面实机）、官方与 Python 同版本烧录已验证。macOS：采集、曲线、界面回读、Python 同版本烧录已验证。Linux：采集、曲线、界面查询、离线烧录回放已验证，尚无实机烧录。macOS、Linux 实机协议扫描仍需验证。各版本可能表现不同。
