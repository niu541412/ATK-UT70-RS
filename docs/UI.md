# 仪表界面编号与行为

`0x03` 查询请求载荷为 `00 00 00 00`，切换载荷为 `编号 01 01 01`。回复第一个载荷字节是即时编号；即时回读不能证明界面稳定、检测完成或 USB 持续正常。编号来自官方 DLL 文档；行为来自 macOS 命令回读和 Windows 官方客户端观察。

| 编号 | 官方名称 | 已观察行为 | Rust 客户端 |
| ---: | --- | --- | --- |
| 0 | 基本测量 | 与波形显示双向切换、回读确认 | 开放 |
| 1 | 波形显示 | 切换正常；版本查询偶发超时，测量仍持续 | 开放 |
| 2 | 数据记录 | 即时回读编号 2，附属功能未验证 | 开放编号切换 |
| 3 | 功能应用 | 即时回读编号 3，附属功能未验证 | 开放编号切换 |
| 4 | 手动触发 | 输出行为未独立验证 | 开放指令发送，状态以仪表显示为准 |
| 5 | 自动检测 | 会启动检测流程，曾导致旧 HID 句柄失效 | 移除负载警告确认后发送指令 |
| 11 | 监控模式 | 官方界面闪一下，外观与基本测量接近 | 开放编号切换 |
| 18 | 线阻模式 | Windows 曾报告 USB 异常；切回其他功能后官方客户端恢复 | 暂不开放 |
| 19 | DASH 检测 | 即时回读编号 19，附属功能未验证 | 开放编号切换 |
| 20 | E-Marker 检测 | 远程切换曾白屏或自行重启，官方客户端也曾白屏；仪表按键可进入检测，稳定性仍需验证 | 列表中显示，但禁止远程切换 |
| 21 | E-Marker 结果页 | 用户停留在检测结果页时，只读 `GetDevUI()` 上报编号 21 | 仅显示当前界面，禁止远程切换 |
| 29 | 设置 | 即时回读编号 29，附属功能未验证 | 开放编号切换 |
| 255 | 其他 | 官方客户端点击后仪表无反应，选择退回前项 | 暂不开放 |

手动触发和自动检测属于有状态操作。客户端发送指令后只标记“已发送”，不把即时回读当作检测完成；自动检测切换前要求确认已移除负载。E-Marker 远程切换曾使仪表白屏或自行重启；白屏时可长按返回键回到菜单。客户端因此禁止发送该远程切换指令，改由仪表按键进入。线阻模式暂缓研究。

Windows E-Marker 线缆实机试验：分别从界面 `5` 和 `0` 发送 `0x03` 切换至 `20`，即时 `0x03` 回复仍分别为 `5` 和 `0`。两次各持续观察约 35 秒，均收到普通 `0x08` 测量帧，未收到可辨认的 E-Marker 线缆详情帧。第二次还收到若干后续 `0x03` 界面编号上报；当前不能仅据此解释检测是否成功。客户端现会接收闲置期间的 `0x03` 上报并同步下拉框。

同一接线下使用官方 DLL `SetDevUI(EMARKERCHECK)` 重试，调用返回 `False`，回调仍报告 `NORMAL`；后续监听未收到线缆详情事件。探测程序只关闭 HID 句柄，没有发送界面恢复指令。用户观察确认远程切换会白屏；仪表按键可进入 E-Marker 检测，但随后一次手动试验出现异常，需要重新拔插仪表，稳定性尚未确认。因此远程切换和手动检测应分开看待。

在用户通过仪表按键进入 E-Marker 检测的 60 秒被动 HID 监听中，收到 3000 个 `0x08` 测量帧和 6 个 `0x03` 界面上报；后者首载荷字节为 `0x11` 与 `0x15`，交替出现。未观察到 `0x20`/`0x21` 或其他独立线缆详情命令。`0x11` 的界面含义尚未确认，不能仅凭编号推断检测结果。

用户随后在仪表上连续手动检测 3 次并停留在 E-Marker 结果页。另一轮 60 秒被动监听只收到 3000 个 `0x08` 测量帧，没有其他命令。停留在结果页时用官方 DLL 执行只读 `GetDevUI()`，回调报告 `21`，可据此标注当前页面；查询没有返回线缆参数。首轮被动监听中的 `0x15` 正是编号 21，但当时每次界面变化与具体按键动作的对应关系仍未确认。

尝试把只读发现的结果页编号 `21` 用作远程切换目标：从 DASH 页面和波形显示页面分别调用官方 DLL `SetDevUI((DevUI)21)`，两次均返回 `False`。第二次持续监听 20 秒没有界面事件，用户确认仪表始终停在波形显示，之后只读查询仍为 `1`；第一次监听中出现的编号 `17` 是用户手动切页产生，不能归因于远程请求。因此 `20` 会白屏，`21` 又不能远程进入结果页，当前没有可安全使用的 E-Marker 远程切换编号。

手动路径中还出现过编号 `17`，因此从波形显示尝试远程设置 `17`：官方 DLL 同样返回 `False`，20 秒内没有界面变化回调，之后只读查询仍为波形显示 `1`。`17` 也不能作为已验证的远程入口。

再次从波形显示发送官方枚举编号 `20`：`SetDevUI(EMARKERCHECK)` 返回 `False`，20 秒监听中没有界面变化回调。用户确认仪表随后自行重启并回到波形显示；探测程序没有发送恢复界面指令。这是远程编号 `20` 的另一种失败表现，不能将 DLL 返回 `False` 解释为没有产生设备侧影响。
