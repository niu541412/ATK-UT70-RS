# UT70 固件与升级模式

本页记录 `.atk` 文件结构和升级回复校验；发送帧前缀见 [指令速查表](UT70%20指令速查表.md)。官方程序及 Python 实现已在硬件 2.7 上完成 V3.5 同版本重刷；**Rust 客户端尚未独立完成实机烧录验证**。仓库不提供固件文件。

## 进入升级模式

拔下侧面 HID 线，按住仪表右键重新插入。升级模式仍使用 VID/PID `19F5:6666`，但 `EE 02` 版本回复的模式字节（载荷偏移 12）为 `01`；应用模式为 `00`。客户端通过按键进入升级模式，不发送尚未实测的 `EE 60` 请求。

## `.atk` 文件

文件由 **32 字节头 + 原样固件镜像**组成，多字节整数为小端：

| 头偏移 | 字段 |
| ---: | --- |
| 0–15 | ASCII 设备类型 `UT70`，后面补零 |
| 16 | 每包数据长度，已验证值 `58` |
| 17 | `encrypt_pos`，含义未确认 |
| 18–19 | `u16` 硬件版本，如 `27` |
| 20–21 | `u16` 应用版本，如 `35` |
| 22–23 | 镜像校验字段，算法未还原 |
| 24–27 | `u32` 镜像字节数，应等于文件长度减 32 |
| 28–31 | `u16` 年、`u8` 月、`u8` 日 |

烧录前必须核对设备类型和硬件版本。头内镜像校验字段由设备校验，客户端将 32 字节头原样发送。

## 升级报告与顺序

去掉 `00` Report ID 后，64 字节报告为 `起始字节 命令 序号 长度 载荷 CRC16 零填充`。请求以 `FB` 开头，回复以 `FA` 开头。CRC16/MODBUS 覆盖起始字节到载荷末尾，初值 `FFFF`、反射多项式 `A001`，低字节先传；载荷最多 58 字节。

| 顺序 | 命令 | 发送内容 | 成功回复 |
| ---: | --- | --- | --- |
| 1 | `10` | 查询设备信息 | 40 字节信息 |
| 2 | `11` | 原样发送 32 字节 `.atk` 头 | `01` |
| 3 | `12` | 开始传输 | `01` |
| 4 | `13` | 固件数据，每包最多 58 字节；序号为回绕的 8 位计数 | 每包 `01` |
| 5 | `14` | 结束传输 | `01`，设备随后重新枚举 |

设备信息的偏移 `0..15` 为设备类型、`16..17` 为硬件版本、`18..19` 为升级模式应用字段、`20..21` 为 Boot 版本、`22..23` 为运行区、`24..35` 为序列号、`36..39` 为日期。升级模式应用字段不能当作已安装版本。每次回复都须匹配命令、序号、CRC 和成功载荷；失败时停止传输。结束后等待设备重新枚举，并重新读取应用模式版本确认可运行。
