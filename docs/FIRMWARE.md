# UT70 固件文件与升级模式接口

这套协议来自一次官方程序对硬件 2.7 的 V3.5 同版本重刷，随后 Python 实现又在 Windows 和 macOS 完成同版本实机烧录。Rust 实现遵循同样的帧布局与状态校验，但**尚未完成独立实机烧录验证**。本仓库不分发官方 `.atk` 文件或原始 USB 抓包。

## 进入升级模式

拔下侧面 HID 线，按住仪表右键重新插入。VID/PID 仍为 `19F5:6666`；`EE 02` 版本回复的第 12 号载荷字节为 `01`，应用模式为 `00`。升级模式不持续上报测量帧。当前客户端通过物理按键进入，不发送未经实机确认的 `EE 60` 命令。

## `.atk` 结构

已验证官方文件是 32 字节头，后面是原样传输的镜像；整数为小端。头的字段如下：

| 偏移 | 类型 | 内容 |
| ---: | --- | --- |
| 0–15 | ASCII | 设备类型 `UT70`，零填充 |
| 16 | `u8` | 每包数据长度，已验证值 `58` |
| 17 | `u8` | `encrypt_pos`，含义未确认 |
| 18–19 | `u16` | 硬件版本，如 `27` |
| 20–21 | `u16` | 应用版本，如 `35` |
| 22–23 | `u16` | 镜像校验字段，算法未还原 |
| 24–27 | `u32` | 镜像字节数，须等于文件长度减 32 |
| 28–31 | `u16`、`u8`、`u8` | 年、月、日 |

样本 V3.5 的 SHA-256 为 `951601748480667208a5b0f72528558ee0f54685f9e4dbce1c5785580ad3be62`，镜像 `307236` 字节，分 5298 包，末包 10 字节。该样本只适用于已验证的硬件版本；其他固件要先核对文件和设备信息。头内镜像校验字段尚不能由主机独立复算，客户端把头原样交给设备校验。

## 升级帧

去掉零 Report ID 后，64 字节数据按 `起始字节 命令 序号 长度 载荷 CRC16 零填充` 排列。请求以 `FB` 开头，回复以 `FA` 开头；CRC16/MODBUS 覆盖起始字节至实际载荷末尾，初值 `FFFF`，反射多项式 `A001`，CRC 低字节先传。载荷最多 58 字节。`FB 10 00 00` 的 CRC 为 `C530`，完整写入前 7 字节为 `00 FB 10 00 00 30 C5`。

| 顺序 | 命令 | 载荷 | 成功回复 |
| ---: | --- | --- | --- |
| 1 | `0x10` 设备信息 | 空 | 40 字节设备信息 |
| 2 | `0x11` 固件信息 | 原始 32 字节 `.atk` 头 | `01` |
| 3 | `0x12` 开始传输 | 空 | `01` |
| 4 | `0x13` 数据 | 每包最多 58 字节；8 位序号从 0 开始回绕 | 每包 `01` |
| 5 | `0x14` 结束传输 | 空 | `01`，设备随后重新枚举 |

设备信息的 0–15 字节是设备类型，16–17 字节是 `u16` 硬件版本，18–19 是升级模式中的应用字段，20–21 是 Boot 版本，22–23 是运行区，24–35 是序列号，36–39 是日期。升级模式应用字段样本为 `12`，不能作为已安装版本。烧录前核对设备类型和硬件版本。每个回复必须匹配命令、序号、CRC 和成功载荷。`0x14` 后等待设备重新枚举，再读应用模式版本；这确认升级流程结束和设备能运行，并非闪存逐字节读回。

原始成功抓包没有负面应答、重发或断电事件；因此异常处理采取停止，不会在未知状态下盲目重发分包。设备可能留在升级模式，必要时可用官方程序恢复。
